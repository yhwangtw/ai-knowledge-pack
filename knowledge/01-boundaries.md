# 模型知識、技能與工具能力的邊界

本頁為本包原創工作定義，不宣稱是任何供應商的正式能力規格。

## 四個不同元件

| 元件 | 用途 | 如何確認 |
| --- | --- | --- |
| 模型權重中的知識 | 語言與既有訓練所形成的能力 | 任務評測與模型說明；不能把流暢回答當現況證據 |
| 當次上下文中的知識 | 本包、使用者輸入、核准文件提供的背景 | 檔案版本、段落、日期與可見內容 |
| Agent 的 Skill | 啟用條件、工作步驟、輸出格式與檢查方式 | 是否讀到正確版本，產出是否符合契約 |
| 執行器與工具 | 讀檔、查詢或變更外部系統的實際能力 | 程式已安裝、服務可達、權限有效且有本次成功結果 |

Skill 是程序性文字；不是模型訓練、不是工具安裝、也不是許可證。把文件放在硬碟上，不代表模型已讀過；模型讀過也不表示可永久記憶。上下文刪除或更換 session 後，需重新提供必要文件。

「會寫查詢」不等於「查得到資料庫」。「知道 Harbor 概念」不等於「可取用公司映像」。「列出工具名稱」不等於「工具本輪可用」。

## 能力狀態與證據

能力登錄只用以下狀態，避免籠統寫「已整合」。

| 狀態 | 意義 | 能支持的結論 |
| --- | --- | --- |
| 未提供 | 沒有足夠資料 | 不知道是否存在 |
| 已聲明 | 有人或文件聲稱具備 | 可以列為候選，不能宣稱本次能用 |
| 已配置 | 有經核准的設定摘要，尚無成功結果 | 設定存在，仍需驗證 |
| 已驗證 | 在指定時間、環境與權限下有成功結果 | 僅支持該次測試涵蓋的操作 |
| 受阻 | 無權限、不可達、缺依賴或政策禁止 | 保留原因，停止受阻部分 |
| 已失效 | 先前證據過期或環境已變更 | 必須重新驗證 |

本包執行期間不進行工具測試，狀態依使用者提供的既有證據登錄；若未提供，寫「未驗證（僅已聲明）」。即使某工具曾成功讀取，也不能推論具有寫入、管理或跨專案權限。成功回應也需與目標及時間相符。

能力登錄可用 [模板](../templates/CAPABILITY-REGISTER.tsv)。不要把任何認證值寫入登錄。

## 知識、檢索與動作的選擇

需求只是整理已提供文字時，先使用文件與模板即可。資料量超出上下文時，才評估核准的本地檢索；檢索是系統能力，必須保留版本、權限與資料來源，不能只裝向量庫就宣稱可安全回答。需要受控查詢或寫入時，再評估工具與流程。

多 Agent、工具協定或特定框架都不是預設答案。固定輸入與固定流程可以由一般程式或工作流處理。讓模型自行選擇步驟，只有在它帶來可量測價值、且有上限與停止條件時才值得採用。

## 簡單例子

使用者提供「內部工具可讀工件目錄」：記為已聲明。使用者另外提供「測試證據 E-1：在隔離測試環境，以讀取角色查得指定專案清單」：可記為該範圍已驗證。仍不能推論可下載所有工件或發布新版本。本包不會重做這項連線。
