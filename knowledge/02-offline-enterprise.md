# 企業無外連環境與 Nexus／Harbor

這裡的「無外連」是不得連向企業核准邊界以外；可否使用內部網路服務，仍依政策與授權。完全斷網的單機則連內網也不可假設可用。

## 先盤點五個層次

1. 推論：模型權重與 tokenizer 是否在本地，授權是否允許公司用途，推論是否會把文字送往外部。
2. 執行：agent、編輯器、作業系統、驅動、執行庫是否已核准且可在無外連時啟動。
3. 工件：直接與間接相依項、建置外掛、基礎映像、模型檔、詞表與各平台版本是否完整。
4. 服務：公司內部 DNS、憑證信任、身分驗證、授權與必要服務是否在隔離邊界內可用。
5. 背景行為：自動更新、遠端模型備援、套件遙測、外部搜尋、外部日誌／追蹤與錯誤回報是否被核准設定與邊界控制涵蓋。

這些是待查項目。本包不提供修改設定的程式，也不替公司宣告「已離線」。

## Nexus 的常見角色

依 Sonatype 官方 repository types 的定義，hosted 存放管理的工件；proxy 會快取遠端內容，缺件或快取條件觸發時可能需要遠端；group 聚合多個 repository。這只是類型概念，不是公司實際配置。[來源 S-02](../governance/SOURCES.md)

本包建議：由管理員維護已核准且有完整清單的工件集合，指定內部解析來源；評估 proxy cache miss、metadata 重查、group 成員與相依項是否可能導向外部。不能假設快取過頂層套件就有完整離線相依項。缺件時保留阻擋，交既有匯入流程處理。

## Harbor 的常見角色

Harbor 官方 2.14.0 文件區分 online 與 offline installer；後者包含 Harbor 所需的預建映像，適用於安裝主機無法上網的情況。這不代表使用者工作負載、模型或所有掃描資料都包含其中。[來源 S-03](../governance/SOURCES.md)

本包建議：工作負載映像另外盤點作業系統／CPU 架構、基礎層、精確 digest、相依服務與匯入證據。映像 tag 可被改動，部署判斷宜對照核准 digest。掃描器的漏洞資料、簽章信任根及更新途徑需要獨立核准；資料過舊須標明，不可以「掃描通過」代表安全或資料最新。

## 人員主導的交付流程

以下是檢核順序，不是自動化指令。

- 管理員在公司核准的來源取得候選內容，確認允許取得與再散布。
- 建立 [工件清單](../templates/ARTIFACT-INVENTORY.tsv)：名稱、版本、雜湊、相依項、平台、授權、取得與核准日期。
- 按現有政策做安全檢查、憑證／機密資料檢查、授權檢查及必要的人工核准。
- 使用核准媒介移入隔離區；重新核對內容與清單，以既有流程放入內部 repository。
- 在隔離測試環境，使用已核准的工具與測試資料確認缺件、更新與外連均被正確處理。
- 記錄結果與回復上一版的方法；未核准前不覆蓋既有版本。

Nexus 與 Harbor 是工件治理的一部分，不是繞過隔離政策的通道。缺件不改連公共來源、不借用個人權杖、不要求暫時關閉 TLS 或安全控管。所有實際連線與發布均屬公司管理員的獨立作業。
