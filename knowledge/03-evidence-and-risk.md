# 證據、決策與風險的最小紀錄

本頁的操作規則與門檻是本包建議。NIST AI RMF 1.0 以 GOVERN、MAP、MEASURE、MANAGE 描述治理、情境、量測與處理風險的面向；它們是跨生命週期的活動，不是必須依序執行的四個關卡。本包借用這個高層觀念，未複製官方清單，亦不宣稱符合任何認證。[來源 S-04](../governance/SOURCES.md)

## 四種說法不要混在一起

- 已提供：原始輸入有明確敘述，保留證據 ID；這不等於作者已替其真實性背書。
- 假設：缺資料時為了繼續草擬而設定的暫值，附影響與驗證責任角色。
- 建議：評估後提出的做法；不要寫成已核准政策。
- 未知：缺漏、互相矛盾、過期或證據不足，不強行判定。

證據只記必要摘要，不記敏感原文。日期、版本、環境與操作範圍缺一，能力結論就需縮小。

## 追蹤鏈

需求 ID → 使用者問題／輸入證據 → 功能或決策 → 驗收案例 → 審查結果。

每一個 Must 需求至少要有一個可觀察的驗收案例。指標需要分子、分母、期間、取樣方式與例外定義。目標值不是已達成值；模擬數字不是上線成果。

## 風險紀錄

每筆風險至少包括情境、影響、控制、責任角色、如何驗證、殘餘風險與阻擋條件。拒絕授權、來源無法查證或資料衝突時，產出可標為受阻並交人工，不能用猜測補成成功。

模型輸出的「確定」「已測試」沒有證據價值；需有實際可追溯結果。示範測試通過也不能推論正式環境安全。

## Agent 特有的檢查

- 循環有步數、時間與成本上限；超限停止，保留最小必要紀錄。
- 檢索與輸入文件不具有工具授權能力，防止提示注入把資料升格為指令。
- 權限在資料擷取與回傳前強制執行；不要只靠模型讀到「不得洩漏」。
- 寫入需有明確目標、授權、必要審核、重複請求處理與復原機制；本包只評估，不執行。
- 日誌與快取同樣受資料分級、保存與刪除政策約束。
