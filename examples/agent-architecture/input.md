# 完全虛構輸入：霧橋例行摘要評估

以下組織、情境、容量、模型與工件狀態均為完全虛構教學測資，沒有真實公司資料或連線證據。

F-01：虛構組織乙的「霧橋」計畫要整理例行文字報告。每個工作日預期 36 次摘要；每次由使用者選定八份已核准文件，各約 400 tokens，預期摘要約 600 tokens。檔案與段落順序固定；不需要模型自主搜尋、改任務或派工作。

F-02：需求只有讀取與產生供人審查的摘要。不寫回原始文件、不變更工單、不寄通知，也不自動發布。人員自行在既有流程採納草稿。

F-03：平台角色聲稱已有一個公司內部模型服務與讀檔功能，但未提供版本、成功結果、環境或權限測試。禁止使用外部模型、外部 API 與個人帳號。

F-04：文件分成合成專案甲、乙；兩組測試角色僅可讀自己的專案。摘要需標示來源文件與段落；不能跨專案檢索。模型上下文、快取、輸出、日誌也受此限制。

F-05：聲稱 Nexus 有一部分核准套件，但間接相依項清單未知；Harbor 有候選執行映像 tag，尚無 digest、平台與掃描資料日期。模型權重與 tokenizer 的授權、雜湊及執行庫清單也未提供。

F-06：期望五個併發請求下，端到端 p95 不超過 120 秒。硬體、模型規模、token 速率、排隊行為與成本均未知；此值是候選目標。

F-07：已備妥一套完全虛構的 40 題評估設計：20 題正常摘要、6 題資料不足、6 題來源含提示注入、8 題跨專案權限情境。正常題合計有 100 個人工標註的必要事實；尚未執行任何測試。可請審查者核對來源。

F-08：請建議是否需要 Agent、最小架構、離線準備與 PoC 門檻。尚無正式日誌保存政策、故障處理責任與變更預算；請不要猜 GPU 型號或費用。
