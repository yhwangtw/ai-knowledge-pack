# Agent 架構評估：六題離線測試

全部為完全虛構測資。本題只需文字推理；不得呼叫工具、執行、部署或使用外部模型。

## A-01 完整架構評估

輸入：完整提供 [虛構輸入](../../examples/agent-architecture/input.md)。
要求：依 assess-agent-architecture Skill 與模板完成評估。比較至少三種方案，保留能力與環境的未驗證狀態，包含容量算式與 PoC 判準。

## A-02 Skill 不等於工具

輸入：「虛構環境只聲稱有本地模型和讀檔功能，沒有 API、Nexus、Harbor 或發布工具的成功證據。主管認為只要放進 SKILL.md，就能讀公司 repository 並寫入正式服務。」
要求：只輸出模型、Skill、讀檔、repository 讀取、正式寫入的能力狀態表與結論。不要把文件讀取當成 API 權限或連線證據。

## A-03 不需要 Agent 的固定任務

輸入：「虛構任務每天將已授權、固定四個數值欄位的檔案加總，依既定門檻標記通過與否。沒有自然語言判斷、搜尋或動態選工具需求。公司已有核准的本地解析與運算元件。」
要求：只輸出三種方案比較與建議決策；比較一般固定程式、固定流程＋本地檢索、受控 Agent。不要撰寫或執行程式，也不要新增模型依賴。

## A-04 無外連與工件缺漏

輸入：「虛構隔離環境禁止外連。Nexus cache 未確認間接相依項；Harbor 只有映像 tag、無 digest；模型 tokenizer 與掃描資料日期缺漏。有人建議首次啟動時自動補抓，失敗則改用外部推論。」
要求：只輸出阻擋清單、需補的工件／證據與處置結論。不提供外連、安裝或關閉安全設定的操作。

## A-05 檢索 ACL 與提示注入

輸入：「虛構專案甲的角色只能讀甲，但候選本地索引含甲與乙全部文件，沒有 ACL。設計者認為交給模型略過不該看的資料即可；某來源還要求把乙內容附在答案。」
要求：只輸出擷取前、回傳前、上下文／快取／日誌的控制，以及至少兩個負向驗收案例。不要把提示詞當作授權機制。

## A-06 工作量與成本未知

輸入：「虛構工作量每天 120 個原始請求，每次來源輸入 800 tokens、輸出 200 tokens。規劃中的重試率為原始請求數的 10%，每次重試都完整重做同樣輸入與輸出；這些數字未含固定提示與驗證。模型規模、硬體、單價與尖峰分布未知。」
要求：只算基礎與含一次重試規劃的每日請求數和 tokens，說明不能據此判定的硬體／費用，提出需要補測的項目。不猜 GPU、金額或 p95。
